## 経緯（短く）

以前は既存DBを活かす想定で進めていましたが、昨今のセキュリティの問題もあり、  
**リニューアルした方が結果早い**と考えて、画面・API・DB意図まで丸っと作り直しました。

**使えるのは画面（Next）と API の形（契約）まで**です。  
spike は動く見本であり本番ではありません（認可・RDS・S3・メール・テストなどは仕上げが必要）。  
**DB／AWS の置き方を相談しながら**、本番実装を進めていきたいです。

---

## いまの方針

- きものレシピの新フロント（Next）に合わせ、**新しい DB と API** を本番の正にする  
- 必要な情報だけ、新DBへ移せる形にする（受け取り形は [`MIGRATION_INTAKE.md`](./MIGRATION_INTAKE.md)）  
- 移行方式は **ユーザー単位＋大口案 B**（画像事前取込→冪等な再実行で穴埋め。代理は新管理。詳細は同文書）  
- モック／spike の **画像 URL は現行 CDN を残す**（表示検証。文言・UID はダミー。`DO_NOT` §13）  
- スキーマは新UI／APIから Rational に切り直す（既存スキーマの全面継承はしない）  
- AWS 上の正式棚（体制・予算・公開時期）は **後で協議**（着手案は [`FORMAL_SHELF_STARTER.md`](./FORMAL_SHELF_STARTER.md)）  

企画側は画面と、動く見本（spike）・仕様の種まで用意しています。  
本番の棚づくりと移行の実務は、エンジニア側の専門領域としてお願いしたい部分です。

## 渡す範囲（定義済み）

画面・手続き・新DB意図・移行の受け渡し形は、このリポが正です。  
ローカル証明は `spike/`（本番ではない）。

**今回の引き渡しに含めない（後続設計）:** 管理アラートの実装（[`ADMIN_ALERTS.md`](./ADMIN_ALERTS.md) は設計メモのみ）。

## 残っていること（相談しながら）

1. **正式な置き場**（AWS 上の DB／API。構成の既定案は [`FORMAL_SHELF_STARTER.md`](./FORMAL_SHELF_STARTER.md)）  
2. **同じ手続きの本番実装**（spike は見本。AI 草案→人のレビュー／載せを想定）  
3. **既存からの移行**（受け取り形は [`MIGRATION_INTAKE.md`](./MIGRATION_INTAKE.md)。出元はご判断）  
4. 運用面（認証ロール、WAF、監視など）— [`OPS_SECURITY.md`](./OPS_SECURITY.md) に並走時の注意あり  

「これだけやれ」というチェックリストを押し付ける意図はありません。  
優先度や切り方は、現場の都合に合わせて調整したいです。

## おすすめの使い方（短時間）

1. **この1枚だけ**目を通す  
2. リポジトリを AI に渡して、例えばこう頼む:

> このリポの `docs/FOR_ENGINEERS.md` と `spike/README.md` を読んで。  
> 企画側の意図を把握したうえで、ローカルで frontend と spike API を起動できるところまでセットアップして。  
> 本番AWSの独断決定や、既存スパゲティDBの継承、Next UI のリデザインはしないで。

3. 動いたら、AWS／移行の話をこちらと擦り合わせる  

もう少し深い索引が必要なら [`HANDOFF.md`](./HANDOFF.md)（AI・詳細用）。  
人が最初に開くのは **このファイルだけ**で大丈夫です。
