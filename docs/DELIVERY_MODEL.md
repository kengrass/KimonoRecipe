# 提供モデル（役割分担）

経緯は [`FOR_ENGINEERS.md`](./FOR_ENGINEERS.md) を参照（**スタート地点の定義も同ファイル**）。

## 言葉の定義（誤読防止）

| 言葉 | 意味するもの | 意味しないもの |
|------|--------------|----------------|
| **提供済み／完成品（企画側）** | UI と API の**形**、新DBの**意図**、モック／spike による動く証明 | 本番公開可能な実行基盤一式 |
| **本番化／正式棚** | AWS 上の API＋DB＋メディア＋実メール等への実装と受け入れ | spike をそのまま外向けに出すこと |
| **spike＝見本** | 手続きどおり動くことの証明。穴は本番で作り直す前提 | コピーして本番にしてよい完成コード |

**このリポジトリ単体を「そのまま本番に出せる」とは書いていないし、そう想定していない。**  
「不完全」「公開不可」は、正式棚が未着手であることの言い換えとして正しい。スタート地点の認識合わせが先。

---

## 基本方針

フロントと API の「形」は **企画側** が契約どおりに揃えて渡す。  
新UI／APIから合理的に **新DBを設計**し、必要な情報だけ移行する。  
エンジニア側は、同じ手続きを **正式な棚（AWS 上の API＋DB）** に載せる。置き方・体制・時期は協議。

```
[企画側が提供・メンテ]
  Next UI
  API 手続き（パス・クエリ・JSON）
  新DB仕様（意図）
  モック／spike（動く証明・任意・本番ではない）

[エンジニア側がやる・協議して決める]
  新DBスキーマの本番実装（AWS）
  同じ API 手続きの本番実装（認可・メディア・メール含む）
  既存からの必要データ移行（出元は問わない／受け取り形は MIGRATION_INTAKE）
  公開判定・WAF・監視などの受け入れ
```

**spike／Supabase＝本番ではない。** 仕様どおり作ると動く、という証明用。  
spike の穴をそのまま本番に写さない（認可・画像所有・実メール等は正式棚で担保）。  
→ [`NEW_DB.md`](./NEW_DB.md) ・ [`../spike/docs/API.md`](../spike/docs/API.md)

## 触ってよい / 触らない

| | エンジニア側 |
|--|------|
| **やる** | 契約どおりの API を新DB上で実装する |
| **やる** | 公開／非公開・所有者判定をサーバで担保する |
| **やる** | AWS 上の DB／API 配置を企画と協議して決める |
| **やらない** | Next UI の画面・IA・コンポーネントの再設計 |
| **やらない** | エンドポイント名・クエリ・レスポンス形の独自変更 |
| **やらない** | 公開 API に非公開を混ぜる／全件返してフロントで絞る |
| **やらない** | 既存スパゲティスキーマを新系の正として継承する |
| **やらない** | spike＝本番、または「提供済み＝公開可」と読み替える |

契約を変えたい場合は **先に企画側へ提案**。エンジニア側が契約を発行しない。
